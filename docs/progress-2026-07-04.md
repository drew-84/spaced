## 1. Email domain validation — from MOCK to REAL ✅

**Before:** `src/lib/email-validation.ts` was a mock. It only rejected the `.test`
TLD and accepted everything else without checking whether the domain actually
existed. There was a `TODO(Arturo)` to wire the real backend. No API endpoint
existed.

**Now:**
- New endpoint **`POST /api/validate-email-domain`** — does a real DNS **MX-record
  lookup** via Node's `dns.resolveMx()`. If a domain has no mail servers (dead
  domain, typo'd TLD, nonexistent), it fails.
- The client (`validateEmailDomain`) now calls this real endpoint instead of the
  mock. Fails **open** on network errors so a transient outage never blocks a
  real user from signing up.

**Verified (curl):**
| Domain | Result |
|---|---|
| gmail.com, hotmail.com | valid ✅ |
| example.test | invalid ✅ |
| thisdomaindoesnotexist-xyz99999.com | invalid ✅ |
| empty / malformed input | invalid ✅ |

This means an email like `andres@amaazon.com` (nonexistent domain) now correctly
triggers "Email inválido" — not because of spelling, but because the domain
doesn't resolve in DNS.

## 2. Hybrid domain typo suggestions (heuristics + AI) ✅ (AI layer pending key)

**The gap we identified:** DNS catches *dead* domains, but not *misspellings of
live ones*. `amaazon.com` might be a real (typosquatted) domain that resolves —
DNS wouldn't flag it, but it's clearly a typo of `amazon.com`. So we added a
suggestion layer, surfaced as a tappable "¿Quisiste decir amazon.com?" hint next
to the error.

Built as **two layers, cheapest first:**

**Layer 1 — Local heuristics (instant, free, no API):**
- Keyboard-adjacency-weighted **Damerau-Levenshtein** distance against the 8 most
  common providers (gmail, hotmail, outlook, yahoo, icloud, live, proton).
- Catches transpositions (`gmial`→`gmail`), deletions (`yaho`→`yahoo`), and
  fat-finger adjacent-key subs (`gnail`→`gmail`).
- Tight distance threshold → very few false positives; legit/obscure domains
  correctly get no suggestion.

**Layer 2 — AI fallback (Claude Haiku 4.5):**
- New endpoint **`POST /api/suggest-email-domain`**.
- Only called when the domain is DNS-dead AND local heuristics found nothing —
  so the common cases stay free and instant; the AI handles only the long tail
  (`amaazon.com`→`amazon.com`, obscure brand typos).
- Returns a suggestion or null; **degrades gracefully** to "no suggestion" on any
  error (missing key, rate limit, model error). Never blocks signup.

**Verified (local heuristics, no key needed):** all common typos corrected
instantly; legit and already-correct domains correctly return no suggestion.

**Cost (for reference):** Haiku 4.5 at ~$0.0003 per call, and the AI only fires on
the rare tail case. Realistic bill: ~1 cent/month at 1,000 signups, ~$1/month at
100,000 signups. No fixed/setup cost — prepaid, pay-per-use.
